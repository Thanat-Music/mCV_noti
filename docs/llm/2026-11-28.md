## Final design decisions

| Source | Small type line | Card |
| --- | --- | --- |
| homework command / initial summary | HOMEWORK | Dark burgundy homework layout |
| Deadline reminder | HOMEWORK DUE | Dark burgundy homework layout |
| Snapshot discovers new work | NEW ASSIGNMENT | Dark blue homework layout |
| Snapshot detects changed deadline | DEADLINE UPDATED | Dark amber homework layout |
| Incoming assignment push | ASSIGNMENT UPDATE | Pale blue notification layout |
| Material / score / announcement push | MATERIAL / SCORE / ANNOUNCEMENT | Pale teal / indigo / purple notification layout |

Homework has a small (`sm`) type line above the large bold (`xl`) course name. Assignment names have no duplicate NEW/Update tags. It retains due date, remaining time, submission status and blue Detail button, with white/muted light text on a uniform dark background. Timestamp notes are embedded, not separate messages. Empty homework results use the dark style too.

All homework content lives in one body container with controlled margins and non-expanding text flex. This replaces separate header/body/footer regions that produced undesirable carousel spacing. Original JSON templates are preserved and adapted at rendering time.

Light notifications have one tinted background, a subtle 1px rounded outline, a small type line, large course name, content title (`lg`), actual message if supplied, and one relevant action button. No redundant status pills or invented filler text. Service incident/recovery notices have no unnecessary course action.

## Immediate webhook command delivery

The old daemon refreshed CourseVille before sending outbox messages and then slept up to five seconds. Commands using saved data could still wait for the refresh and polling cycle.

- `Engine.delivery_ready` is an asyncio event per account. `_queue()` sets it after inserting an outbox row. The synchronous webhook transaction completes before the event loop can schedule the sender.
- `delivery.py` runs one independent sender coroutine per account. LINE HTTP calls use `asyncio.to_thread`; engine/SQLite operations stay on the event-loop thread.
- The worker clears the signal before draining, sends additional ready batches immediately, and waits for a queue event, shutdown, or five-second retry-discovery fallback.
- Startup drains durable work; retry keys, frozen payloads, backoff and event dedupe remain intact.
- The daemon starts/stops this worker and detects unexpected exit. The same daemon serves standalone and multi-user modes.
- Dry-run starts no sender. One-shot send mode drains explicitly after refresh instead of starting a competing sender.
- HTTP webhook responses do not wait for LINE delivery. This removes the intentional polling/refresh wait, not network latency or time behind an already active send.
- Signup replies still use the separate existing enrollment delivery loop.

## Real push data and remaining distinction

The supplied processed payloads confirm all four suffixes: Assignment, Material, Score and Announcement. Announcement is no longer marked unverified in preferences/help.

`message` is the course name, `title` ends with the type suffix, and `url` targets the content. Score URLs may only target the course. Icon paths are not classification signals. Rendering strips the final suffix and retains the original HTTPS CourseVille link, with homepage fallback for missing/unsafe links.

New push outbox text stores the payload in a JSON `_flex_push` envelope to preserve course/title/body/link fields. Legacy plain-text rows remain supported.

An incoming Assignment update push does not say whether work is new or a deadline changed. Snapshot comparison produces those two specific events. They remain independent, so a push and a detected change can both notify. Refresh-first suppression of redundant assignment pushes was proposed but **not implemented**. Do not claim cross-source deduplication is complete.

## Developer utilities

```powershell
python scripts/preview_line.py
python scripts/update_line_user.py
```

- Preview performs a real send to local account `u1`: 13 cards in five message objects in one request (four homework variants and nine distinct historical pushes). It consumes push quota.
- `scripts/notification_samples.json` stores supplied course/title/link samples, including the Thai announcement. Repeated Lab 9 is shown once. Historical previews are labeled.
- Homework preview Detail buttons open CourseVille's homepage rather than nonexistent demo assignments. Historical notification links remain original.
- The recipient updater prompts for a LINE Messaging API ID, validates `U` plus 32 hex characters, rejects duplicate recipients and refuses a missing database. It changes only u1's recipient plus revision/audit metadata, preserving encrypted CourseVille credentials.
- Default utility database is the repository's `database/main.db`. Use `--database` explicitly to update another database. Updating a local copy does not update Pi production state.
- Utilities use standard-library HTTP/SQLite and local rendering code. The installer copies runtime modules/assets, not these checkout-only scripts/samples.
